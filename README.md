# Course Terra

A minimal, professional online course-selling web application.

## Architecture

This is a monorepo consisting of:
- **Frontend**: React + Vite + TypeScript + Tailwind CSS, deployed on Vercel.
- **Backend**: Python + Flask, deployed on Render.
- **Database/Auth/Storage**: Supabase (PostgreSQL).

## Tech Stack
- React, TailwindCSS, React Router
- Python, Flask, Gunicorn
- Supabase Auth, PostgreSQL, Storage

## Local Development

### 1. Supabase Setup
1. Create a Supabase project.
2. Run the SQL in `supabase/migrations/01_initial_schema.sql` in the SQL Editor.
3. Enable Email/Password authentication in Auth settings.
4. Create two storage buckets: `course-thumbnails` (Public) and `course-content` (Private).

### 2. Admin Setup & Seeding
1. The system automatically promotes `jkkhond@gmail.com` to `admin` upon signup.
2. Sign up on the frontend using `jkkhond@gmail.com`.
3. Once the account is created, run the `supabase/seed.sql` script in the Supabase SQL editor to create the initial "Mathematics" course.

### 3. Backend Setup
```bash
cd backend
python -m venv venv
source venv/bin/activate  # or venv\Scripts\activate on Windows
pip install -r requirements.txt
```
Copy `.env.example` to `.env` and fill in the values.
Start the backend:
```bash
python run.py
```

### 4. Frontend Setup
```bash
cd frontend
npm install
```
Copy `.env.example` to `.env` and fill in the public Supabase keys.
Start the frontend:
```bash
npm run dev
```

## Payment Architecture
Razorpay payment integration is fully architected but **intentionally disabled** (`PAYMENTS_ENABLED=false`).
The backend includes `/api/v1/payments/create-order` and webhook endpoints ready for future integration.
When you are ready to enable payments:
1. Provide Razorpay Live Credentials in the Render environment variables.
2. Set `PAYMENTS_ENABLED=true`.
3. Wire the frontend Razorpay checkout modal to handle the order ID from `create-order`.

## Security Considerations
- The Supabase Service Role Key is ONLY used on the backend.
- Row Level Security (RLS) protects data access.
- `jkkhond@gmail.com` is protected as the sole admin via database trigger logic.
- Protected course assets are served via secure temporary signed URLs generated by the backend.
